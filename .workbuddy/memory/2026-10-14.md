# 2026-10-14

## 插花小助手小程序（网页版 → 微信小程序移植）

- 新建 `miniprogram/`（微信小程序工程，appid 测试号 touristappid），功能对齐网页版：62 花材三分类、拖拽调高度/倾角、换色、层级、撤销、16 容器 × 3 色、背景切换、完成作品导出相册。
- 核心技术决策：**SVG 滤镜（绿幕抠图/换色）小程序无法实现 → 离线烘焙**。流水线在 `tools/`：
  - `gen-flowers.js`：按行提取 app.js 纯函数（避开 DOM 绑定行）生成 flowers.html（241 个烘焙单元：花材×花色×变体 + 叶片零件 + 花瓶缩略图×3色）
  - `rasterize.js`：playwright-core + 本机 Chrome（channel:'chrome'，免下载 Chromium）截透明 PNG
  - `process.py`：PIL 裁透明边/缩放/webp + 生成 manifest（**锚点计算要加 .bake 的 34px padding**，曾因此返工）
  - `gen-preview.js`：浏览器预览页做视觉校验（需 wx stub + 图片相对路径注意层级）
- 花瓶：自研 `utils/svgpath.js` path 解释器（含 A 圆弧转贝塞尔、相对指令），全部 16 容器 Canvas 移植，换色零图片成本。
- 渲染模式四类：head（茎+花头）/ hang（枝顶垂下整束）/ whole（vectorLeaf 整株含茎，xy 非均匀缩放）/ foliage（尤加利等用叶片零件实时拼装）。
- 包体积：主包 111KB，flowerpack 分包 1473KB（<2MB 上限）。
- 素材 138MB webp 原件不打包；重新生成素材命令已写进 README。
- 已知取舍：tone 明度抖动未移植；贺卡/回放/猫/声音/多语言 v1 未做。
- **环境坑**：本仓库在 exFAT 外置盘，macOS 会生成 `._*` AppleDouble 文件（241 个素材变 482 个，险些超分包上限），提交/打包前需 `find . -name '._*' -delete`；该盘 cluster 2MB，du 体积虚高，要用实际字节统计。

## 23:47 真机/模拟器排障：点花不出花
- 用户反馈点击花材后只有花茎没有花头。报错 `wx.createImage is not a function`（基础库 3.17.4）。
- 真因：新版基础库已移除 wx.createImage；Canvas 2D 必须用 canvas 节点 `canvas.createImage()`。修复：SceneRenderer.setCanvas(node) + ensure() 内优先 canvas.createImage()，保留 wx.createImage 兜底。
- 素材格式做成可切换：process.py 默认 webp（flowerpack 单包 1.5MB）；`python3 tools/process.py png` → 量化 PNG + flowerpack/2/3 三分包（各 <2MB）作为 webp 解码兼容兜底。manifest 增加 p（分包）字段，renderer/index 按它拼路径。
- 预览工具 gen-preview.js 的路径替换要跟 renderer 的 assetUrl 函数同步改。
